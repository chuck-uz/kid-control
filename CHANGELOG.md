# История изменений

Здесь описаны все значимые изменения проекта.
Формат — по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [семантическому версионированию](https://semver.org/lang/ru/).
English version: [CHANGELOG.en.md](CHANGELOG.en.md).

## [Unreleased]

### Добавлено
- **Кастомные интервалы в боте.** В меню «⚙️ Интервалы» добавлена кнопка «✏️ Свой
  интервал» — родитель присылает своё значение игра/отдых одним сообщением (например
  `50/10`, `50 10` или `50:10`), а не выбирает из пресетов. Значения проверяются и
  ограничиваются диапазоном 1–1440 минут, чтобы некорректное правило не сломало
  применение политики на агенте.

## [2.5.0] — 2026-08-29

### Добавлено
- **Веб-панель** (`/dashboard`) — сетка всех устройств и детальная карточка с историей;
  вход по админ-ключу (`X-Admin-Key`), автообновление данных. Самодостаточный
  `wwwroot/dashboard.html` поверх REST API `/admin/*`.
- **Графики экранного времени по дням** в карточке устройства — сколько времени за ПК
  каждый день, с максимумом и суммой за период. Учёт активного использования копится в
  `device_usage_daily` (только фаза «игра», пропуски > 3 мин игнорируются, граница суток —
  по Ташкенту).
- **Удалённый скриншот** — запрос снимка экрана ребёнка из Telegram, картинка приходит в чат.
- **Удалённый звук** — голосовое/аудио, отправленное в бот, проигрывается на ПК ребёнка.
- **Уведомления о ночных попытках** — попытка включить ПК в ночное окно шлёт родителю
  уведомление в Telegram (с дедупликацией).

### Изменено
- **Учёт времени при выключенном ПК.** Пока машина выключена или спит, тратится только
  время **перерыва** — игровое время не расходуется (`Session.ApplyOfflineRest`).
  Выключение посреди игры сохраняет остаток; перерыв «дотикивает» в фоне и при следующем
  включении, если он прошёл, сразу начинается игра. Переход через конец ночного окна
  начинает свежий полный игровой день.

## [2.2.0] — 2026-08-29

### Исправлено
- **Самообновление больше не «кирпичит» агента.** В v2.1 служба запускала установщик как
  собственный дочерний процесс, который останавливал и `sc delete`-ал эту же службу —
  обрыв посреди обмена бинарников оставлял машину вообще без службы. Теперь обмен идёт в
  **отдельной одноразовой SYSTEM-задаче планировщика** (вне дерева процессов службы), с
  резервной копией, проверкой здоровья (Running + 8 c стабильности) и **откатом** при
  сбое. Автоустановка снова включена по умолчанию. Проверено «вживую» на реальном ПК
  (2.2.0 → 2.3.0 → 2.4.0 → 2.5.0 без ручного вмешательства).

### Изменено
- **Надёжное определение версии агента** (E2) — версия читается из `ProductVersion`
  исполняемого файла (устойчиво для single-file), с откатом на атрибут/AssemblyVersion;
  `0.0.0` и `+sha` отбрасываются. Реальная версия видна в боте и в панели.

## [2.1.0] — 2026-08-28

### Добавлено
- **Fleet-бэкенд** — управляемый парк агентов: enrollment (bearer-токен), heartbeat со
  статусом, длинный опрос команд, desired-state и политики. ASP.NET Core minimal API,
  EF Core 8 + Npgsql (snake_case), миграции на старте.
- **Управление из Telegram** — статус, «дать время», блокировка/разблокировка, правка
  правил (игра/перерыв/ночь), экстренная разблокировка по одноразовому коду, выбор
  целевой версии агента и обновление.
- **Развёртывание** — Docker Compose + Caddy (TLS), инструкция `deploy/DEPLOY.md`; агент
  ставится скриптом `deploy.bat`, обновляется `update.bat`.

## [2.0.0] — 2026-08-23

### Изменено
- **Полное переписывание v1 → v2.** Монолитный установщик (~1900 строк `InstallerForm`,
  мешавший UI, управление службой, HTTP-клиент, ACL, реестр, P/Invoke и самообновление)
  разложен на маленькие классы с единственной ответственностью и headless-путём
  оркестрации. Доменные правила выделены в чистый, тестируемый слой без зависимостей.

### Добавлено
- **Слоистая архитектура** (Domain · Contracts · Application · Infrastructure · Platform ·
  Hosts · Installer) со строгими правилами зависимостей.
- **Безопасность** — Authenticode-гейт самообновления, admin-only командный канал,
  rate-limited OTP, атомарные записи состояния в ACL-защищённом ProgramData, защита ключа
  службы в реестре. Полная модель угроз — в [SECURITY.md](SECURITY.md).
- **CI/CD** — сборка и тесты на каждый push/PR; релиз по тегу `vX.Y.Z` с `SHA256SUMS.txt`.

### Удалено
- Отладочная телеметрия, писавшая в захардкоженный `C:\kid-control\…\debug.log`.
