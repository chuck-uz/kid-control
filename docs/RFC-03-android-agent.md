# RFC-03 — Android-агент

Статус: **черновик**. Развилка §4 решена: **Device Owner отпадает** (сброс телефона не
вариант), Family Link уже установлен и остаётся жёстким слоем.
Область: добавить во флот второй тип устройства — Android-телефон, управляемый тем же
бекендом и тем же ботом, что и Windows-ПК.

Продолжение [RFC-01](RFC-01-fleet-backend.md) (флот, протокол) и
[RFC-02](RFC-02-phase2.md) (наблюдаемость, медиа).
Общий бюджет времени и одновременная блокировка вынесены в
[RFC-04](RFC-04-shared-budget.md) — это изменение затрагивает и Windows-агента.

---

## 1. Контекст и цель

Флот уже работает: бекенд на `kidcontrol.oresh.in`, бот `@controlkid_bot`, один
Windows-агент в managed-режиме. Телефон ребёнка — вторая половина экранного времени и
сейчас вне контроля.

**Цель:** телефон появляется в списке устройств бота рядом с ПК, с той же моделью
политики (игра/отдых, ночь, пауза, блок), тем же enroll-потоком и той же офлайн-гарантией.

### Не-цели
- iOS (там управление возможно только через MDM с Apple-сертификатом — отдельная история).
- Веб-дашборд, мультиарендность — как и раньше, позже.
- Полный паритет фич с Windows-агентом: §3 показывает, что часть примитивов на Android
  физически отсутствует.

## 2. «Форк» — неверная рамка

Инвентаризация Windows-агента по признаку переносимости:

| Слой | Строк (≈) | Судьба |
|---|---|---|
| `Domain` (Session, NightWindow, ScheduleRule) | ~350 | **Переносится 1:1** — чистая логика, без OS |
| `Fleet.Contracts` (DTO протокола) | ~200 | **Переносится 1:1** — это wire-формат, он общий |
| `Fleet/*` (Client, Reconciler, Appliers, кэш) | ~700 | **Переносится по смыслу** — та же машина состояний, другой HTTP-стек |
| `Application/SessionService` | ~450 | Переносится частично — оркестрация та же, порты другие |
| `Infrastructure/Windows/*`, `Platform`, `Ipc/*` | ~600 | **Выбрасывается целиком** — Win32, named pipes, ACL, SCM |
| `Installer*`, `Update/Authenticode*` | ~2000+ | **Выбрасывается целиком** — у Android своя модель установки |

То есть переносится **логика** (~1700 строк, полностью покрытая тестами), а вся
**правоприменительная** половина — то, ради чего агент существует — строится заново на
принципиально других примитивах. Это не форк, это **второй агент, говорящий на том же
протоколе**. Практическое следствие: общего кода между репозиториями не будет, общим
остаётся `Fleet.Contracts` как спецификация, а не как библиотека.

**Язык:** Kotlin + Jetpack Compose. .NET MAUI позволил бы переиспользовать те самые 1700
строк C#, но ценой борьбы с Doze, Device Owner API и AccessibilityService через
интероп-прослойку — то есть дорого именно в той половине, которая и так пишется заново.
Домен маленький и полностью покрыт тестами; тесты переносятся вместе с ним.

## 3. Пропасть примитивов

| Что делает Windows-агент | Как | Android-эквивалент |
|---|---|---|
| Блокирует игры | `ProcessKiller`, kill по имени | `setPackagesSuspended()` — система сама не даёт запустить |
| Выключает ПК | `shutdown /s` | **Нет.** Ни одно приложение не выключает Android. → `lockNow()` |
| Перезагружает | `shutdown /r` | `DevicePolicyManager.reboot()` — **только Device Owner** |
| Защита от удаления | ACL на ProgramData, SCM recovery, critical process | `setUninstallBlocked()` + `DISALLOW_FACTORY_RESET` + `DISALLOW_SAFE_BOOT` |
| UI поверх экрана | WPF UiHost, отдельная сессия | Overlay (`TYPE_APPLICATION_OVERLAY`) или lock-task |
| IPC служба ↔ UI | Named pipes + ACL | **Не нужен** — одно приложение, один процесс |
| Аварийный OTP | Pipe только для Administrators | Экран в самом приложении (слабее: нет второго уровня доверия) |
| Скриншот | Win32 capture из UiHost | `MediaProjection` — **требует согласия пользователя**, см. §6 |
| Self-update | GitHub Release + Authenticode-гейт | APK-подпись проверяет сама система; тихая установка через DO |
| — | — | **Бонус:** `UsageStatsManager` — какие приложения реально использовались |

Два места, где Android строго слабее и это надо принять заранее:
**выключения не будет** (максимум — блокировка экрана + suspend приложений) и
**тихого скриншота не будет** (см. §6).

## 4. Решение: без Device Owner, слоями

Device Owner провижинится только на устройстве без настроенных аккаунтов, то есть требует
сброса телефона к заводским. Это отклонено. Значит всё, что в §3 помечено «только Device
Owner», недоступно: ни suspend приложений, ни запрета удаления, ни Safe Mode, ни reboot,
ни тихой установки обновлений.

Вместо одного сильного слоя строим три слабых, но перекрывающих друг друга:

| Слой | Что даёт | Чем обходится |
|---|---|---|
| **Family Link** (уже стоит) | Дневной лимит, время сна, блокировка приложений — с системными привилегиями | Не обходится ребёнком, но и **не управляется программно** (нет API) |
| **Свой агент** (AccessibilityService + оверлей) | Одновременный блок за ~1–2 с, точный учёт времени, общий бюджет | Force-stop, отзыв accessibility, удаление приложения |
| **Алерт «офлайн»** (F1, уже работает) | Убил агента — родителю приходит уведомление за 3 минуты | Ничем: сам факт тишины и есть сигнал |

Ключ в том, что слои закрывают дыры друг друга. Свой агент даёт **динамику** (общий
бюджет, одновременность), которой нет у Family Link; Family Link даёт **неотключаемый
потолок**, которого нет у своего агента; F1 превращает обход второго слоя в событие,
которое видит родитель. Обойти всё сразу девятилетний может, но не незаметно.

Family Link при этом надо настроить согласованно: дневной лимит = бюджету из RFC-04,
время сна = ночному окну политики. Это ручная настройка, не код — в runbook.

> Проверить перед реализацией: мешает ли Family Link удалить произвольное сайдлоад-приложение
> (контроль установки у него есть; про удаление — не уверен). Если мешает — второй слой
> заметно крепче.

## 5. Архитектура агента

```
app/
  domain/          Session, NightWindow, ScheduleRule  (порт с C#, тесты переносятся)
  fleet/           FleetClient (OkHttp/Retrofit), Reconciler, Policy/Desired/Command appliers
  store/           DataStore: policy+desired кэш, session_state, processed commands
  enforce/         DevicePolicyController (suspend/lock/reboot), OverlayService, UsageReporter
  ui/              Compose: экран статуса, экран enroll, аварийный OTP
  KidControlService  ForegroundService — часы + heartbeat + long-poll
```

**Живучесть.** Foreground service с постоянным уведомлением (`foregroundServiceType`
объявлен), исключение из battery optimization, перезапуск по `BOOT_COMPLETED`, WorkManager
как watchdog. Часы тикают локально; Doze растягивает интервалы — таймер должен считать по
`SystemClock.elapsedRealtime()` дельтами, а не полагаться на регулярность тиков.
`Session.Tick(elapsed)` уже устроен именно так — принимает дельту, а не «один тик».

**Транспорт.** Тот же long-poll, что у Windows-агента: протокол не меняется, бекенд не
меняется. Интервалы растянуть под телефон (heartbeat 120с, `wait=120`) — это параметры
запроса, не контракт. FCM high-priority как оптимизация батареи — позже, если долгий
polling окажется заметен; он потребует нового эндпоинта на бекенде.

**Офлайн.** Ровно как в §7 RFC-01: политика и desired durable-кэшируются, команды копятся
на бекенде с TTL, дедуп по `command.id`. Логика реконсиляции переносится с
`FleetReconciler` вместе с его шестью интеграционными тестами.

## 6. Скриншот (G1 на Android)

`MediaProjection` требует явного согласия пользователя диалогом и не может быть выдан
тихо ни Device Owner'у, ни кому-либо ещё без системной подписи. Обход в рамках правил:
**запросить согласие один раз при настройке и держать projection живой** внутри
foreground service, переиспользуя её для всех последующих команд `screenshot`. Пересоздание
projection (после перезагрузки телефона, убийства сервиса) снова потребует диалога.

Значит: команда `screenshot` на Android **может вернуть «нет согласия»** и это штатный
ack-с-ошибкой, а не сбой. Бот должен показать это внятно, а не «команда не выполнена».
Эндпоинт `POST /agent/media` и `ScreenshotRelay` переиспользуются как есть.

## 7. Изменения на бекенде

Протокол уже device-agnostic — большая часть работы косметическая:

- **Тип устройства.** `os_info` уже есть и заполняется агентом; добавить в `device`
  явное `platform` (`windows` / `android`), чтобы бот не гадал по строке.
- **Гейтинг возможностей в боте.** Меню устройства сейчас показывает «💻 Выключить» и
  «🔄 Перезагрузить» безусловно. Для Android: выключение скрыть или заменить на
  «🔒 Заблокировать», перезагрузку показывать только при Device Owner.
- **Новые команды.** `lock_now`; `suspend_apps` (payload: список пакетов) — если нужен
  точечный блок вместо тотального.
- **Целевая версия.** `PolicyDto.TargetVersion` переиспользуется, но источник APK и
  проверка подписи другие (§3) — для Android поле означает тег релиза с APK.
- **Не меняется:** enroll, heartbeat, long-poll, ack, media, desired-состояние, аудит,
  алерты офлайн (F1) — всё работает для нового агента без единой правки.

Порядок из RFC-02 сохраняется: бекенд-часть (platform, гейтинг меню, новые типы команд)
деплоится мгновенно и **до** того, как появится первый APK.

## 8. Что нужно решить перед реализацией

1. **Device Owner или нет** (§4) — определяет весь объём работ и требует сброса телефона.
2. **Что именно блокировать**: телефон целиком (lock-task/оверлей) или список приложений
   (`setPackagesSuspended`). Второе гуманнее — звонки и будильник продолжают работать.
3. **Общая или раздельная политика ПК и телефона.** Модель RFC-01 — политика на
   устройство, общего бюджета нет. Для ребёнка «40 минут на ПК + 40 на телефоне» — это
   80 минут; если это не то, что нужно, потребуется общий бюджет (это отход от решения №3
   RFC-01 и отдельная задача на бекенде).
4. **Ночь и звонки.** Ночной блок на телефоне не должен мешать позвонить родителю.

## 9. Милстоуны

Скелет-первым, как в RFC-01.

### Блок J. Бекенд (деплоится сразу, без агента)
- [ ] **J1. `platform` у устройства** + заполнение из `os_info` при enroll.
- [ ] **J2. Гейтинг меню бота по платформе** — Windows-действия не показываются для Android.
- [ ] **J3. Типы команд `lock_now` / `suspend_apps`** в `CommandTypes` и в enqueue-путь.

### Блок K. Агент — сквозной скелет
- [ ] **K1. Порт домена** — Session/NightWindow/ScheduleRule на Kotlin + перенос unit-тестов.
- [ ] **K2. Enroll + heartbeat** — экран ввода кода, токен в EncryptedSharedPreferences,
      устройство появляется в боте и отчитывается статусом. *DoD:* телефон виден в `/all`.
- [ ] **K3. Foreground service + локальные часы** — таймер живёт офлайн, переживает
      перезагрузку. *DoD:* после ребута остаток времени тот же.
- [ ] **K4. Long-poll + реконсиляция** — политика/desired/команды, дедуп, TTL.

### Блок L. Enforcement (без Device Owner)
- [ ] **L1. Мягкий блок** — AccessibilityService следит за активным приложением, оверлей
      на отдых / ночь / force-block. *DoD:* блок из бота накрывает экран за ~1–2 с.
- [ ] **L2. Family Link согласован** — дневной лимит и время сна выставлены под политику;
      шаги в runbook. Не код.
- [ ] **L3. Аварийный OTP** — локальная разблокировка без сети.

### Блок M. Паритет
- [ ] **M1. Обновления** — APK с GitHub Releases; без DO установка требует подтверждения
      пользователя, так что это «скачали и попросили нажать», а не тихий апдейт.
- [ ] **M2. Скриншот** (§6) — согласие один раз, переиспользование projection.
- [ ] **M3. Отчёт об использовании** — `UsageStatsManager` → какие приложения и сколько.
      Совпадает с P1 из [RFC-04](RFC-04-shared-budget.md) и идёт первым: ничего не
      запрещает, поэтому нечего обходить, и сразу даёт цифру, под которую выбирается лимит.

**Порядок:** J (бекенд, сразу) → K (скелет) → M3/P1 (учёт) → L (блокировки) → M1/M2.

## Приложение A. Если всё же Device Owner

Вариант отклонён в §4 из-за сброса телефона, но проработан — на случай пересмотра.
Блоки J, K и M3 от выбора не зависят и делаются в любом случае; меняется только блок L.

### A.1 Ритуал провижининга (один раз, необратимо без второго сброса)

Device Owner ставится **только на устройство без настроенных аккаунтов**. Порядок:

1. Забрать с телефона всё нужное (фото, чаты) — дальше полная очистка.
2. Сброс к заводским настройкам.
3. Пройти мастер настройки, **не входя в Google-аккаунт** — это ключевой шаг, аккаунт
   закрывает окно для провижининга.
4. Настройки → О телефоне → 7 тапов по номеру сборки → Для разработчиков → отладка по USB.
5. `adb install kidcontrol.apk`
6. `adb shell dpm set-device-owner uz.chuck.kidcontrol/.DeviceAdminReceiver`
7. Только теперь добавить Google-аккаунт, поставить Play Store и приложения.

Альтернатива без USB — QR-провижининг: на приветственном экране 6 тапов по пустому месту
открывают сканер, QR несёт ссылку на APK и контрольную сумму подписи. Чище, но требует
выложить APK по URL.

### A.2 Главный вопрос — уживётся ли Family Link

Device Owner на устройстве может быть **только один**. Family Link — это надзор Google
поверх детского аккаунта, и есть основания думать, что fully-managed устройство под чужим
DPC он не супервизирует. То есть Device Owner — скорее **вместо** Family Link, а не
вдобавок к нему.

**Проверить до сброса, на эмуляторе или запасном телефоне.** Если подтвердится, выбор
формулируется честнее: не «усилить контроль», а «заменить зрелый продукт Google своим
кодом», где свой код становится единственной точкой отказа на телефоне ребёнка.

### A.3 Во что превращается enforcement

Блок L из §9 переписывается и **становится проще**, чем мягкий вариант — уходят
AccessibilityService, оверлеи и борьба с battery optimization:

| Задача | Мягкий вариант | С Device Owner |
|---|---|---|
| Заблокировать игры | Следить за foreground + накрыть оверлеем | `setPackagesSuspended()` — система сама не пускает |
| Заблокировать всё | Оверлей на весь экран | `lockNow()` + lock-task |
| Защита агента | Никакой | `setUninstallBlocked()`, `DISALLOW_SAFE_BOOT` |
| Выживание сервиса | Уговоры про battery optimization | DO вносит себя в исключения |
| Обновление | Скачали, попросили нажать | Тихая установка через `PackageInstaller` |
| Перезагрузка | Нет | `reboot()` |

Не появляется даже с Device Owner: **выключение телефона** (нет такого API ни у кого) и
**тихий скриншот** (`MediaProjection` всё равно спрашивает согласие — см. §6).

### A.4 Обязательно: аварийный выход

`DISALLOW_FACTORY_RESET` + `setUninstallBlocked` + сломавшийся агент = кирпич, который не
чинится ничем, кроме сервис-центра. Это ровно тот класс риска, на котором обжёгся
Windows-агент в v2.1 (см. [ARCHITECTURE.md](../ARCHITECTURE.md), «update trust model»), только
последствия хуже — там был мёртвый сервис, здесь мёртвый телефон.

Поэтому до включения любых ограничений:
- локальный экран с OTP → `clearDeviceOwnerApp()`, работающий **без сети и без бекенда**;
- `DISALLOW_FACTORY_RESET` включать в последнюю очередь и осознанно, а лучше не включать:
  сброс ребёнком и так виден по алерту F1 «офлайн», а цена ошибки несопоставима.

### A.5 Что меняется в RFC-04

Трёхслойный компромисс §4 схлопывается в один слой: `ForceBlocked` приезжает long-poll'ом
за секунду-две и превращается в `setPackagesSuspended` — блок телефона становится таким же
неотменяемым, как на ПК. Алерт F1 из основного механизма защиты становится приятным
дополнением. Учёт активности, тикер бюджета и всё содержимое блоков N/O
[RFC-04](RFC-04-shared-budget.md) — без изменений.
