# RFC-04 — Общий бюджет времени и одновременная блокировка

Статус: **черновик**, нужен выбор варианта в §3 и решение по §5.
Область: один бюджет экранного времени на ребёнка вместо независимых таймеров на каждом
устройстве, и блокировка всех устройств одновременно при его исчерпании.

Меняет решение №3 [RFC-01](RFC-01-fleet-backend.md) («политика привязана к устройству,
общего бюджета нет») и частично №10 (разделение state/command). Связан с
[RFC-03](RFC-03-android-agent.md) — телефон без Device Owner.

---

## 1. Задача

Сейчас каждое устройство считает своё время само: `Session` живёт в агенте, `device_status`
на бекенде — **только для показа** («never drives enforcement»). Два устройства = два
независимых таймера, то есть «40 минут игры» превращается в 80.

Нужно: один счётчик на ребёнка, и когда он исчерпан — блокируются **все** устройства
одновременно.

---

## 2. Хорошая новость: доставка одновременной блокировки уже есть

Механизм не надо изобретать, он собран в Phase 1:

- `DeviceDesired.ForceBlocked` — версионируемое состояние, реконсилится агентом.
- `CommandSignal.Notify(deviceId)` — будит long-poll устройства мгновенно.
- `FleetDesiredApplier` — применяет блок идемпотентно, с приоритетом над таймером.

Бекенду достаточно выставить `ForceBlocked` всем устройствам ребёнка и дёрнуть `Notify`
для каждого — агенты применят блок **в пределах секунды-двух** друг от друга. Это уже
проверено в T7 («long-poll просыпается за ~1с»).

Настоящая работа — не в доставке, а в **учёте**: кто владеет счётчиком и что считается
использованием.

---

## 3. Варианты для телефона

Device Owner отпал (сброс телефона не вариант), Family Link уже стоит. Автоматически
заблокировать телефон в тот же момент, что и ПК, можно ровно тремя способами:

| | Способ | Одновременность | Обходится ребёнком | Цена |
|---|---|---|---|---|
| **A** | Свой Android-агент, оверлей поверх экрана | ~1–2 с | Да: force-stop, отзыв accessibility, удаление | Новое приложение (RFC-03, блоки K+L2) |
| **B** | Сетевой блок на роутере по MAC/IP телефона | мгновенно | Нет — но только в домашнем Wi-Fi, мобильные данные обходят | Интеграция бекенда с роутером |
| **C** | Family Link «Заблокировать устройство» | нет, вручную | Нет | Родитель жмёт кнопку по алерту в боте |

Четвёртого нет: **у Family Link нет публичного API**, дневной лимит и время сна не
меняются программно. Family Link — это статический потолок, а не управляемый слой.

**Рекомендация — A + C как слои, B опционально.**
Свой агент даёт одновременность и точный учёт; Family Link остаётся жёстким потолком
снизу (дневной лимит = тот же бюджет, время сна = ночное окно), так что обход мягкого
блока упирается в лимит, который не обходится. Если ребёнок убьёт агента — устройство
перестанет слать heartbeat и **уже существующий алерт F1** («офлайн») придёт родителю
в бот за 3 минуты. Тампер-детектор получается бесплатно.

B стоит добавить, если телефон в основном дома и на Wi-Fi: это единственный
неотключаемый с телефона рычаг, доступный без Device Owner. Требует роутера с API
(MikroTik / OpenWRT / Keenetic), известного MAC и **выключенной рандомизации MAC** для
домашней сети.

## 4. Учёт: кто владеет счётчиком

Бюджет общий ⇒ его владелец — **бекенд**. Это разворот текущего разделения: сейчас агент
владеет часами, бекенд только отображает.

```
child_budget (tenant_id, date, limit_minutes, consumed_seconds, version)
device       + active_until : timestamp   -- продлевается heartbeat'ом, пока агент активен
```

Фоновый сервис бекенда раз в ~5 секунд: если **хоть одно** устройство активно
(`active_until > now`) — прибавить 5 секунд к `consumed_seconds`. При достижении лимита —
выставить `ForceBlocked` всем устройствам ребёнка, поднять версию desired, `Notify`
каждому. Сброс в местную полночь (бекенд уже живёт в `TZ=Asia/Tashkent`).

**Союз, а не сумма.** Счётчик тикает раз в реальную секунду, в которую активно хотя бы
одно устройство, — то есть считается экранное время ребёнка, а не устройство-часы.
Иначе игра на ПК с телефоном в руке съедала бы бюджет вдвое быстрее, что выглядит как
баг, даже если формально «честно». Если хочется наоборот (наказывать за два экрана
сразу) — это одна строка в тикере.

**Что считается активностью.** Нового требования не было при пер-девайсных таймерах, а
здесь оно обязательно: включённый, но простаивающий ПК не должен есть общий бюджет.
- Windows: `GetLastInputInfo`, простой меньше ~60 с ⇒ активен.
- Android: экран включён и разблокирован.

Это единственное изменение, которое придётся внести в **Windows-агент** — плюс отчёт
флага наверх.

---

## 5. Как бюджет уживается с циклом игра/отдых

Сейчас модель — только цикл 40/20 без дневного потолка. Предлагаю не заменять, а
сложить: цикл 40/20 остаётся как перерывы для глаз (теперь **глобальный** — отдых
наступает на всех устройствах сразу), дневной бюджет — отдельный потолок сверху.

Решить надо: **должен ли отдых быть глобальным**. Если да — 20 минут отдыха означают,
что и телефон тоже недоступен, и это, вероятно, и есть смысл перерыва. Если нет — цикл
остаётся пер-девайсным, а общим будет только дневной бюджет.

---

## 6. Офлайн

Общий бюджет по определению требует связи: два агента не могут согласовать один счётчик
без арбитра. Поведение при недоступности бекенда:

- Агент продолжает применять **последнюю известную политику и остаток бюджета** из
  durable-кэша, списывая его локально. Расхождение возможно, если офлайн оба устройства
  сразу — принимаем.
- На реконнекте бекенд — источник истины: агент отправляет потреблённое за офлайн,
  бекенд сливает и возвращает актуальный остаток.
- `ForceBlocked`, выставленный пока устройство было офлайн, применяется на реконнекте —
  это уже работает (T8).

---

## 7. Изменения в контракте

Мелкие и обратно совместимые (`FleetJson` толерантен к незнакомым/отсутствующим полям,
это проверено тестами T1):

- `StatusReportDto` **+** `IsActive: bool`, `ConsumedSecondsDelta: int` — сколько активных
  секунд агент насчитал с прошлого heartbeat (для офлайн-слива).
- `HeartbeatResponse` **+** `Budget: BudgetDto?` — `{ limitMinutes, remainingSeconds, version }`,
  присылается по тому же принципу дельты, что политика.
- `PolicyDto` **+** `DailyBudgetMinutes: int` (0 ⇒ бюджет выключен, поведение как сейчас).

Старый агент, не знающий новых полей, продолжает работать по пер-девайсной модели —
миграция не ломающая.

---

## 8. Милстоуны

### Блок N. Бекенд (деплоится сразу, без агентов)
- [ ] **N1. Сущность бюджета + миграция**, сброс в местную полночь.
- [ ] **N2. Тикер и одновременный блок** — фоновый сервис, `ForceBlocked` всем + `Notify`.
      *DoD:* руками выставляю `consumed = limit` → ПК блокируется за секунды.
- [ ] **N3. Бот** — показ остатка на день, правка лимита, «добавить N минут к сегодняшнему».

### Блок O. Windows-агент (один релиз)
- [ ] **O1. Детект активности** (`GetLastInputInfo`) + флаг в heartbeat.
- [ ] **O2. Применение бюджета** — остаток из heartbeat, локальное списание, блок при нуле.

### Блок P. Телефон
- [ ] **P1. Reporter-приложение** — только `UsageStatsManager` + heartbeat, без блокировок.
      Даёт настоящую общую картину до всякого enforcement. *DoD:* телефон виден в `/all`,
      его активность списывает общий бюджет, ПК блокируется с учётом телефона.
- [ ] **P2. Мягкий блок** — оверлей (RFC-03, L2).
- [ ] **P3. Family Link как потолок** — дневной лимит = бюджету, время сна = ночному окну.
      Ручная настройка, не код; занести в runbook.
- [ ] **P4. (опц.) Сетевой блок** на роутере — вариант B из §3.

**Порядок:** N → O → P1 → P2/P3 → P4.
P1 стоит раньше блокировок: он ничего не запрещает, поэтому его нечего обходить, и он
сразу отвечает на вопрос «сколько ребёнок на самом деле сидит в телефоне» — без этого
числа лимит выбирается наугад.
