# RFC-02 — Phase 2 (после запуска флота)

Продолжение [RFC-01](RFC-01-fleet-backend.md). Phase 1 (T1–T13 + блок E) дал рабочий флот:
бекенд по HTTPS, бот в бекенде, managed-агент (enroll/heartbeat/команды/desired/обновления),
переименование устройств. Phase 2 — наблюдаемость, медиа и удобство оператора.

## Принцип очерёдности
**Бекенд-only задачи идут первыми.** Бекенд деплоится мгновенно (пересборка образа → `docker
load` → recreate). Изменения агента требуют нового релиза И переустановки на каждом ПК —
дороже, поэтому группируются и идут реже. Порядок ниже это учитывает.

## Задачи

### Блок F. Наблюдаемость (бекенд-only — без обновления агента)
- [x] **F1. Алерты «офлайн/снова на связи».** Фоновый сервис: если `last_seen` устройства
      старше порога (старт: 3 мин) — уведомить админов в боте; при возврате — «снова на связи».
      Анти-спам: одно уведомление на переход состояния. *DoD:* выключаю ПК → в течение порога
      приходит алерт; включаю → приходит «снова на связи».
      *Готово:* `AlertBackgroundService` (порог/интервал из `Alerts:*`, дефолт 180/60с),
      анти-спам по переходу состояния, прайминг на первом проходе (рестарт бекенда не спамит),
      рассылка всем админам из `admin`-таблицы. 4 теста граничной логики `IsOffline`. Бекенд-only.
- [x] **F2. История/аудит в боте.** Кнопка «🧾 История» в меню устройства → последние N
      записей `audit` (правки политики, команды, пауза/блок, enroll/rename) читаемо.
      *DoD:* последние действия по устройству видны из бота.
      *Готово:* `GetHistoryAsync` (15 последних) + `HistoryTextAsync` с человекочитаемыми
      ярлыками (правка политики/пауза/переименование/+время/…), кнопка «🧾 История». 2 теста.
- [x] **F3. Экран «всё под контролем».** Обзор `/all` (и inline «📋 Все устройства»)
      показывает по каждому устройству: онлайн/офлайн, статус, остаток времени и флаги
      🚫 блок / ⏸️ пауза / 🌙 ночь; те же флаги — в детальном статусе устройства.

### Блок G. Медиа-реле (нужен релиз агента) — закрывает «Phase 2» кнопки в боте
- [x] **G1. Загрузка скриншота.** Кнопка «📷 Скриншот» → команда `screenshot` c `uploadId` →
      агент снимает экран (UiHost IPC) → `POST /agent/media?uploadId=…` → `ScreenshotRelay`
      отправляет фото в чат, который запросил (проверка device+TTL). Бэкенд/бот задеплоены;
      агентская половина (FleetCommandApplier.ApplyScreenshotAsync + FleetClient.UploadMediaAsync)
      вышла в **v2.3.0**. *DoD:* кнопка присылает картинку в бота (после обновления агента до v2.3.0).
- [x] **G2. Воспроизведение аудио.** Оператор шлёт голосовое/аудио в бот → бот скачивает файл,
      кладёт в `AudioRelay` для выбранного устройства → команда `play_audio` c `mediaId` → агент
      тянет из `GET /agent/audio?mediaId=…` и играет (UiHost, OGG/Opus). Вышло в v2.4.0.

### Блок H. Обновления и эксплуатация
- [x] **H1. Управление версией из бота.** «📦 Версия» показывает текущую версию агента и
      целевую (latest / закреплённый тег); кнопки «🆕 Следить за latest», «📌 Закрепить <тек.>»,
      «✏️ Задать версию» (ввод тега сообщением) и «⬇️ Обновить сейчас». Пишет
      `DevicePolicy.TargetVersion` (бампит политику → агент подхватывает на heartbeat).
- [x] **H2. Ночные попытки.** Агент уже детектит попытку (Worker → NotifyNightUsageAttempt,
      с троттлингом); время последней попытки уходит в heartbeat-статусе, бекенд шлёт алерт
      операторам один раз на каждое новое значение (in-memory dedup), время — ташкентское. Вышло в v2.4.0.

### Блок I (позже) — крупное
- [x] **I1. Веб-дашборд** на том же API (read-only v1). `wwwroot/dashboard.html` (self-contained,
      тёмная тема, 8-pt сетка) на `https://kidcontrol.oresh.in/dashboard.html` (алиас `/dashboard`).
      Вход по admin-key (`X-Admin-Key`, хранится в localStorage), сетка устройств (онлайн/офлайн,
      статус, остаток/♾️, флаги 🚫/⏸️/🌙, версия), детальная панель с политикой и историей
      (`GET /admin/devices/{id}/history`), автообновление 15 с. Бекенд-only. *Дальше по желанию:*
      действия из веба (пауза/блок/+время) через существующие `POST /admin/*`.
- [ ] **I2. Мультиарендность** (несколько семей на одном бекенде).

## Порядок
F1 → F2/F3 (бекенд-only, деплой сразу) → затем один релиз агента, закрывающий G1/G2/H2 →
H1 (бекенд) → I (по потребности).

## Заметки по дизайну
- Медиа-хранилище: старт — файлы в volume бекенда (`/data/media`), ретенция по времени.
  Позже — при веб-дашборде — вынести в объектное хранилище, если понадобится.
- Алерты: анти-спам через переход состояния; тихие часы — по потребности (ночью ПК офлайн —
  это норма, не спамить).
