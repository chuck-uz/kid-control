## Зачем

Родительский контроль обычно живёт на одном ПК: чтобы что-то изменить, надо сесть за
машину ребёнка. KidControl устроен как **парк управляемых агентов**: на каждом детском
компьютере стоит фоновый агент, а родитель управляет всеми машинами удалённо — из
**Telegram-бота** или **веб-панели**. Дать 15 минут, включить блокировку, посмотреть
скриншот, узнать сколько времени сегодня провели за компьютером — всё это делается с
телефона, не подходя к ПК.

Агент — это служба Windows уровня LocalSystem: она считает экранное время по правилам
(игра/перерыв), блокирует экран в ночное окно и переживает перезагрузки, а обновляется
сама — по релизам из этого репозитория, без ручного вмешательства.

## Возможности

- **Экранное время по интервалам** — правило «игра N минут / перерыв M минут» с таймером
  на экране ребёнка; по истечении игры появляется оверлей перерыва. Пока ПК выключен или
  спит, тратится только время перерыва — игровое время не расходуется, поэтому выключение
  посреди игры сохраняет остаток, а перерыв «дотикивает» в фоне.
- **Ночная блокировка** — в заданном окне (например, 22:00–07:00) экран блокируется;
  первое включение после ночи начинает свежий полный игровой день.
- **Управление из Telegram** — статус ПК, «дать время», блокировка/разблокировка,
  правка правил (игра/перерыв/ночь), экстренная разблокировка по одноразовому коду,
  выбор целевой версии агента и обновление «на месте».
- **Уведомления о ночных попытках** — если ребёнок пытается включить ПК в ночное окно,
  родителю приходит уведомление в Telegram (с дедупликацией — не спамит).
- **Удалённый скриншот** — запросить снимок экрана ребёнка прямо из бота, картинка
  приходит в чат.
- **Удалённый звук** — проиграть на ПК ребёнка голосовое/аудио, отправленное в бот
  (позвать к телефону, предупредить голосом).
- **Веб-панель** — сетка всех устройств, детальная карточка с историей и **графиками
  экранного времени по дням**; вход по админ-ключу, автообновление данных.
- **Надёжное самообновление** — агент сам подхватывает новые релизы. Обмен бинарников
  идёт в отдельной одноразовой SYSTEM-задаче планировщика (вне дерева процессов службы),
  с резервной копией и откатом при сбое — обновление не может «окирпичить» агента.
- **Переживает перезагрузки** — состояние таймера хранится в защищённом ACL каталоге
  `%ProgramData%`, пишется атомарно; после ребута/обновления остаток времени
  восстанавливается, а не сбрасывается.

## Как это устроено

```
┌─────────────────────┐        HTTPS (enroll · heartbeat · long-poll)      ┌──────────────────────┐
│  Агент на ПК ребёнка │ ───────────────────────────────────────────────► │   Fleet-бэкенд        │
│  ServiceHost (SYSTEM)│ ◄─────────────────────────────────────────────── │   ASP.NET Core + EF   │
│  UiHost (per-user)   │        desired-state · policy · команды           │   PostgreSQL          │
└─────────────────────┘                                                    └──────────┬───────────┘
        таймер, ночь,                                                                  │
        скриншот, звук                                              Telegram-бот ◄──────┤
                                                                    Веб-панель  ◄──────┘
                                                                    (родитель управляет парком)
```

- **Агент** (`KidControl.ServiceHost` + `KidControl.UiHost`) применяет правила локально,
  шлёт heartbeat со статусом и длинным опросом забирает команды; чистый доменный движок
  интервалов (`KidControl.Domain` / `Application`) не зависит от часов и тестируется offline.
- **Бэкенд** (`KidControl.Backend`) — минимальный API на ASP.NET Core, EF Core + Npgsql
  (snake_case), миграции применяются на старте; внутри же крутится Telegram-бот и
  отдаётся `wwwroot/dashboard.html`.
- **Релизы** собираются на GitHub Actions (windows-latest) по тегу `vX.Y.Z`, а агент
  обновляется сам. Подробности — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Установка агента (ПК ребёнка)

Нужен Windows 10/11 и права администратора. Установка — одним скриптом (ставит .NET 8
Desktop Runtime через winget при необходимости, регистрирует службу, прописывает
подключение к парку и включает самообновление):

```bat
deploy.bat
```

Скрипт скачивает последний релиз, ставит агента «тихо» и записывает защищённый
`%ProgramData%\KidControl\appsettings.json` (адрес парка, код привязки, автообновление).
Обновить уже установленного агента вручную:

```bat
update.bat
```

Полный сценарий развёртывания парка (бэкенд, DNS, TLS) — в [deploy/DEPLOY.md](deploy/DEPLOY.md).

## Управление (родитель)

| Задача | Где |
|---|---|
| Статус ПК, сколько времени осталось | Telegram: `/status` |
| Дать время / заблокировать / разблокировать | Кнопки в боте |
| Изменить правила (игра / перерыв / ночь) | Бот → политика устройства |
| Экстренная разблокировка по коду | Бот → одноразовый OTP |
| Скриншот экрана ребёнка | Бот → «Скриншот» |
| Проиграть голос/аудио на ПК | Отправить голосовое в бот |
| Выбрать версию агента / обновить | Бот → версии |
| Обзор всех устройств + графики по дням | Веб-панель `/dashboard` (вход по админ-ключу) |

## Требования

- **Агент:** Windows 10/11, .NET 8 Desktop Runtime (ставится автоматически), права
  администратора на установку.
- **Бэкенд:** Docker + PostgreSQL (или готовый `docker-compose` из `deploy/`), домен с TLS.
- Telegram-бот (токен от [@BotFather](https://t.me/BotFather)).

## Сборка

```powershell
# Windows, .NET 8 SDK
./build.ps1        # clean → restore → build (Release) → тесты → publish в ./publish
```

`build.ps1` падает на любой ошибке и собирает framework-dependent single-file win-x64
бинарники. Бэкенд (`KidControl.Backend`, `net8.0`) и доменные слои собираются и на
Linux/macOS; проекты агента (`net8.0-windows`) — только на Windows. CI
(`.github/workflows/ci.yml`) гоняет тот же build + тесты на каждый push и PR.

Развёртывание бэкенда парка — [deploy/DEPLOY.md](deploy/DEPLOY.md) (Docker Compose +
Caddy для TLS).

## Безопасность и приватность

Противник в модели угроз — **сам ребёнок за консолью**, возможно с правами локального
администратора. KidControl делает защиту надёжной против обычного пользователя и
заметным, аудируемым препятствием (а не абсолютной стеной) против админ-ребёнка:
Authenticode-подпись обновлений, admin-only командный канал, rate-limited OTP,
атомарные записи состояния в ACL-защищённом ProgramData, защита ключа службы в реестре.
Токен бота и список админов — секреты; они живут только в защищённом `appsettings.json`
и **никогда** не попадают в код, логи или коммиты. Полная модель угроз и честные
ограничения — в [SECURITY.md](SECURITY.md).
